How the updater sees the budget

V is the model's budget measure and V* its limit. The flat view supplies this normalized volume row first, followed by the scenario's extra constraints. Ordinary SIMP uses physical material volume; SINH can use effective resource cost instead. A local-stress augmented-Lagrangian response is a penalty with its own multipliers and must be paired with the updater that understands it.

A displayed step can contain several physics evaluations

engine evaluates current design ─> updater
                                  ├─ optional trial evaluations
                                  ├─ optional conservative corrections
                                  └─ next design ─> display physical field

The composed method's recorded objective belongs to the evaluation before its returned update; displayed density/volume belongs to the returned design. The Batch 3 driver closes any optimizer thread and then evaluates the final design again. Its report labels this extra evaluation separately. GCMMA, line searches and external callbacks can make step counts incomparable.

The three standalone level-set methods evolve their own fields and volume control. They bypass the composable representation/filter/updater chain and use linear p=1 ersatz stiffness. Their compliance values should not be ranked against density methods using p=3 as if only the updater had changed.

Preparing for nested GUI functions

The current GUI can reuse stable IDs, Param definitions, capability checks, plain research descriptions and the existing forward/backward interfaces. The descriptions import no GUI code. Adding a new view does not require changing these numerical functions.

For later execution of nested functions, the hard decisions are shared variable ownership, field shapes/units, state and derivative lifetimes, cache invalidation after parameter changes, and how independent branches join their gradients. The current VariantModel combines repeated evaluations of shared variables; it is a useful reference, not a general multiphysics network. The external-loop handshake also needs an explicit lifecycle if a future graph owns execution.

No new graph executor, objectives or physics adapters were introduced here. The GUI effort can plan those boundaries while these documented interfaces stay available for adaptation.
