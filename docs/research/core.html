How Toporia computes a design

A function here means a numerical building block, not every Python def. An optimization method can contain several functions; supporting infrastructure constructs, runs, records or displays them. This guide describes the current implementation, rather than specifying the GUI colleague's forthcoming network.

1. Describe the job

Run = Scenario + Solver + Output. The scenario holds the domain, material, supports, loads, measured objective and limits. The solver chooses functions, mesh resolution and stopping settings. Output controls saved results and post-processing. A preset is a recipe for these objects, not a new algorithm.

The current mesh factory produces rectangular Q4 grids or H8 boxes. Element fields have shape (nely, nelx) or (nelz, nely, nelx); a representation's design variables can have another shape. Coordinates and units are defined by the scenario; the baseline paper examples use normalized stiffness and forces.

Code: run.py, scenario.py, solver.py, mesh.py.

OC here requires element-density variables, suitable gradient signs and a single volume budget. MMA and external optimizers have different contracts; compatibility is checked before execution. The optimizer internally uses summed densities with budget ; dividing both by the cell count gives the mean-density constraint above.

The engine applies explicit schedules before each step. Inside ComposedMethod, the order is evaluate → advance internal continuation → update → form new physical density. A step reports the old design's evaluated objective beside the new design's density. A fresh final objective therefore needs another solve. That distinction is retained in the research reports.

The ordinary stopping test compares this change to tolerance. Selected nonlinear representations also monitor physical-density motion. The engine holds stopping while continuation remains active, can accept a method-specific criterion, and always applies the iteration cap. Small motion alone proves neither feasibility nor a globally optimal or binary design. Post-processors then compute diagnostics or exports; thresholding changes the design and needs its own validation.

Code: composition.py, oc.py, loop.py, postprocess.py.

Which functions contain which other functions?

Container Current contents Boundary
Composed optimization method One model and one updater Compatibility is the intersection of their capabilities.
Assembled model Representation, filter pipeline, physics/material law, responses One evaluation produces values and gradients.
Filter chain Ordered filters Each intermediate input is retained for the backward pass.
Variant model Several evaluations of the same design under varied settings A mean or smooth worst case combines values and gradients.
Whole method Its own numerical algorithm and any internal helpers Existing level-set methods do not necessarily expose the same subfunctions.
Run Scenario, solver and output settings A job recipe, not an arbitrary executable network.

Preparing for the GUI framework

Existing keys such as filter:density and model:q4 identify numerical parts; Param already describes settings; capabilities and physics feature contracts already reject incompatible choices. Keep these as adaptation points. Research descriptions are plain data and can be reused in a new view without solver changes.

Current assumptions to revisit for larger tasks are structured element-field shapes, one scalar physical density, mesh-derived supports/loads, and response features tied to today's engines. Multiple fields, unstructured meshes and transient states need deliberate interface extensions and numerical validation. This batch introduces no replacement execution graph or new solver contracts.
